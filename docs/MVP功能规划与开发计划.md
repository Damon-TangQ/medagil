# Medagil AI MVP 功能规划与开发计划

**文档类型：** 技术架构文档  
**创建日期：** 2026年1月20日
**最后更新：** 2026年1月23日 Pax
**版本：** v1.0  
**适用范围：** Medagil AI 医学科研写作AI智能体平台 （第一期MVP）


## 1. 文档目的

本文件用于从**产品视角**汇总医学科研写作 AI 智能体平台（Medagil AI）在 **MVP 阶段（4–6 个月）** 的：

- **功能列表**：围绕临床医生/科研人员在论文撰写、润色、翻译三个核心场景的必要功能，按端拆分（Web 用户端、小程序用户端、Web 管理端）。
- **开发计划排期**：在 4–6 个月周期内的阶段目标与关键交付。

仅关注 MVP 范围内的“最小可行功能”，不涵盖基金申请、毕业课题、科普等后续阶段能力。

---

## 2. MVP 目标与范围

### 2.1 总体目标

- **产品目标**：在 **4–6 个月内** 交付一个可在线体验的 MVP 版本，验证“医学科研写作 AI 智能体”对临床医生/科研人员在：
  - 临床医学论文撰写（临床论著助手·精简版）、
  - 中英文论文润色、
  - 医学场景翻译
   这三个核心场景的**真实使用价值**。

- **用户范围**：
  - 临床医生、住院/主治医师
  - 医学院/附属医院的硕博研究生
  - 小规模种子用户为主（几十到几百人级别），用于快速迭代验证。

### 2.2 功能范围边界

- **本期“必须有”**：
  - 临床论著助手（精简版）
  - 论文润色助手
  - 医学翻译助手
  - Web 用户端：项目/文档管理 + 智能体工作区
  - 小程序用户端（精简版）：润色 + 翻译的轻量入口
  - Web 管理端：基础监控 + 智能体和模型管理配置

- **本期“不做 / 延后”**：
  - 基金申请智能体、毕业课题智能体、科普写作智能体
  - 高级协作（多人实时协同编辑）、复杂报表、大规模运营后台
  - 复杂付费/计费体系

## 2.3 技术策略

- **LLM 与工作流平台**：统一采用**购买的 Dify 云服务版本**作为 AI 应用与工作流平台：
  - **MVP 阶段采用 Dify 云服务**：通过购买 Dify 企业云服务版本，直接调用平台 API 接入各大模型，节约前期的运维成本和部署维护成本。
  - 在 Dify 云服务中分别配置：
    - 「临床论著助手（精简版)」应用
    - 「论文润色助手」应用
    - 「医学翻译助手」应用
  - 使用 Dify 的工作流与数据集能力，减少自研 Prompt/工作流代码量。
  - **后续扩展**：根据业务发展和数据安全需求，后续可评估私有化部署方案（如自建 Dify 平台或迁移至本地化模型服务）。
- **自研后端**：
  - 搭建 AI 网关服务，对接 Dify 云服务与 Web / 小程序 / 管理端。
  - 提供统一的业务 API（如：生成论著结构、润色文本、翻译文本、记录调用日志等）。
- **支付与会员服务**：
  - MVP 阶段统一采用**微信支付**作为唯一支付通道：Web 端通过微信扫码支付完成订阅，小程序端通过微信小程序支付能力完成订阅。
  - 所有订阅状态与订单数据统一由"会员/订阅服务"管理，Web 与小程序仅作为前端入口，不各自维护订阅状态。

## 3. MVP 功能列表

### 3.1 AI 智能体功能

#### 3.1.1 临床论著助手（精简版）

- **定位**：帮助临床医生在既有研究基础上，快速成型标准 IMRAD 结构的临床论著初稿。
- **MVP 功能点（粗颗粒度）**：
  - 研究信息采集表单：研究主题、设计类型（回顾性/前瞻性等）、样本量、主要终点等。
  - IMRAD 结构框架生成：自动输出标题占位、引言/方法/结果/讨论的章节结构与二级标题建议。
  - 引言/讨论初稿生成：基于用户提供的研究背景与核心结果，生成可修改的文本初稿。
  - 结果落地：支持一键将生成内容写入指定项目文档（如“论著初稿.docx”）。
- **MVP 明确不做**：复杂统计方法自动匹配、自动生成图表、与外部文献库的深度联动。

#### 3.1.2 论文润色助手

- **定位**：为中英文科研论文提供专业的语言润色，重点解决语法、术语和学术表达问题。
- **MVP 功能点**：
  - 文本输入方式：粘贴文本，或从项目文档中选取段落。
  - 语法与拼写检查：高优先级错误标记（语法错误、拼写错误、明显用词错误）。
  - 医学术语与统计表达规范：如 hypertension vs high blood pressure、P 值表达、均值±标准差等。
  - 学术表达优化：将口语化/中式英语改写为更符合 SCI 论文风格的表达。
  - 修订视图（基础版）：显示原文与润色后文本，并突出关键修改区域。

#### 3.1.3 医学翻译助手

- **定位**：面向医学科研/临床文稿的中英互译，重点保证术语准确与句子通顺。
- **MVP 功能点**：
  - 中英双向短文本翻译（≤ 500 字）。
  - 术语优先：基于医学术语表（如 MeSH）进行专业翻译，避免通用机翻错误。
  - 长难句拆分与重组：在不暴露技术细节的前提下，保证译文逻辑清晰、语气正式。

### 3.2 Web 用户端（PC 浏览器）

- **定位**：MVP 的主入口，承载完整的“项目管理 → 文档管理 → 调用智能体 → 输出结果落地”的闭环。

- **MVP 功能点**：
  - 账户与认证：注册/登录、退出登录、查看与修改基础个人信息（姓名、单位、专业方向）。
  - 项目管理：
    - 创建/查看/归档项目（字段包括项目名称、研究类型、目标期刊、截止日期）。
    - 项目列表与搜索（按名称/状态筛选）。
  - 文档管理：
    - 文档上传：Word、PDF、TXT、Markdown，限制单文件大小）。
    - **Word 文档交互式渲染与编辑**：
      - **在线查看**：支持 Word 文档（.docx）在线渲染显示，保留格式（字体、段落、样式），支持图片、表格展示。
      - **在线编辑**：支持富文本编辑器直接编辑 Word 文档内容（文本修改、格式调整、插入图片/表格），编辑后自动同步保存。
      - **专业性文档支持**：保留医学论文常用的样式（标题层级、引用格式、脚注等），确保专业文档要求。
    - **PDF/TXT 文档查看**：PDF 文档在线预览，TXT 文档支持 Markdown 简化渲染。
    - 文档版本管理（MVP 简化版）：
      - 自动保存最近 3 个版本快照（每次保存覆盖最旧版本）。
      - 支持版本对比功能（显示当前版本与历史版本的差异，标注新增/删除内容）。
      - 支持一键回溯至历史版本。
  - 智能体工作区：
    - 在项目内打开智能体会话界面，选择使用：临床论著助手（精简版）/ 论文润色助手 / 医学翻译助手。
    - **聊天式交互与流式输出**：
      - 支持 Markdown 渲染（代码块、列表、表格等）。
      - **流式输出展示**：AI 生成内容实时逐字渲染，提升用户体验（避免长时间等待）。
      - **Word 文档交互式写入**：支持将 AI 生成的内容实时流式写入 Word 文档，用户可边生成边查看文档更新。
    - 支持将生成结果一键写入指定的项目文档或新建文档。
  - 会员与订阅：
    - 在 Web 端展示当前用户的订阅套餐与有效期（从统一会员/订阅服务读取）。
    - 支持选择订阅套餐（基础版/专业版）并发起订阅/续费（通过微信扫码支付完成，保留支付成功/失败状态），订阅结果写入统一会员服务。
    - 套餐对比页面：展示基础版与专业版的核心差异（如调用次数、文档数量限制、可用智能体等），引导用户选择合适套餐。

### 3.3 小程序用户端（微信（优先））

- **定位**：为临床医生、学生提供“随手用”的轻量入口，集中验证**润色 + 翻译**的高频需求，写作能力可以后置。

- **MVP 功能点（精简版）**：
  - 平台授权登录：基于微信/抖音等平台的授权登录，并与主站账号绑定。
  - 快速翻译：输入短文本（≤ 500 字），一键调用"医学翻译助手"，返回译文并可复制/分享。
  - 快速润色：输入英文段落，调用"论文润色助手"，返回润色版本与简要提示（如"修正语法 X 处、术语优化 Y 处"）。
  - 简单历史记录：最近若干条润色/翻译记录展示，支持复制再次使用。
  - 会员订阅同步：展示与 Web 端一致的订阅状态，支持在小程序内发起/续费订阅（选择基础版/专业版），订阅支付通过微信小程序支付完成，订阅数据通过统一会员服务与 Web 端保持同步。

- **数据同步范围（MVP 明确边界）**：
  - ✅ **同步功能**：订阅状态（套餐类型、有效期、剩余配额）、历史记录（润色/翻译记录）。
  - ❌ **暂不支持**：项目管理（小程序端不展示 Web 端创建的项目）、文档编辑（小程序端仅支持快速输入，不支持编辑 Web 端文档）。
  - **使用说明**：小程序端专注于"随手用"的轻量场景（快速润色/翻译），复杂的项目管理和文档编辑请使用 Web 端。

### 3.4 Web 管理端（运营/技术后台）

- **定位**：内部使用的运维/运营入口，用于观察 MVP 运行情况，进行基础配置，不面向终端用户。

- **MVP 功能点**：
  - 用户与项目概览：
    - 用户总数、活跃用户数（按日/周/月粗粒度统计）。
    - 项目、文档数量概览。
  - AI 调用监控：
    - 按时间维度查看 AI 调用次数、成功率、错误类型统计。
    - 按智能体类型（写作/润色/翻译）筛选查看。
  - 智能体与大模型管理：
    - 按智能体维度查看所使用的大模型配置（模型名称、提供商、温度、最大 Token 等）。
    - 支持为单个智能体切换绑定的 Dify 应用 / 工作流版本（例如从 V1 切换到 V2），用于灰度升级。
  - Dify 应用映射与配置：
    - 为三个核心智能体维护对应的 Dify 应用 ID / Workflow ID、模型选择及关键参数（温度、最大 Token 等）。
    - 提供只读查看和基础配置编辑能力（例如启用/停用某个 Dify 应用）。
  - 订阅与订单基础管理：
    - 订阅套餐配置：创建和管理订阅套餐（如基础版、专业版），配置套餐的时长（月度/季度/年度）、价格、权益（调用次数、文档数量限制、可用智能体等），支持套餐上架/下架控制。
    - 用户订阅管理：按用户查看订阅状态与有效期，支持导出基础订阅列表。
    - 订单与异常监控：粗粒度查看支付/订阅失败记录，用于排查问题（不做复杂财务对账）。
  - 第三方服务接入管理：
    - 列表展示已接入的第三方服务（如数据服务、短信服务、OSS 对象存储等），包含服务名称、提供商、当前状态等基础信息。
    - 支持启用/停用某个第三方服务，并为后端预留配置入口（例如回调地址、限流参数，仅做简单表单配置）。
  - 微信管理：
    - 小程序运营配置：配置小程序端的基础运营文案（如首页引导语、功能说明、常见问题入口链接），管理功能开关（如润色/翻译是否开放、实验性功能控制）。
    - 小程序核心配置：配置 AppID、环境（测试/生产）、域名/回调地址等关键参数，确保与后端和微信开放平台配置一致。
    - （预留后续公众号管理能力接入空间）。
  - 支付管理：
    - 配置微信支付相关参数（商户号、API 密钥、回调地址等），支持测试/生产环境切换（基础开关即可），为 Web 扫码支付与小程序支付提供统一配置中心。
    - （预留后续支付宝或其他支付渠道接入空间）。
  - 日志查询与分析：
    - 系统日志查询：查看系统运行日志（如服务启动/停止、异常错误、性能瓶颈等），支持按时间、日志级别（ERROR/WARN/INFO）筛选。
    - API 调用日志：查看后端 API 调用记录（请求路径、响应时间、状态码、错误信息等），支持按接口、用户、时间维度筛选，用于排查接口异常。
    - AI 调用日志：查看 Dify 云服务调用记录（调用时间、智能体类型、模型选择、Token 消耗、响应时长、成功/失败状态等），支持导出日志用于成本分析和性能优化。
  - 用户反馈与工单管理（基础版）：
    - 用户反馈列表：查看用户提交的反馈（功能建议、问题报告），显示反馈内容、提交时间、用户信息。
    - 工单状态管理：标记工单状态（待处理/处理中/已解决/已关闭），支持添加处理备注。
  - 系统公告管理（基础版）：
    - 公告发布：发布系统公告（如维护通知、功能更新说明），设置公告生效时间与展示位置（Web 端首页/小程序端首页）。
    - 公告管理：查看历史公告，支持编辑/删除公告。
  - 系统权限管理：
    - 用户管理：管理后台系统用户（增删改查、启用/禁用状态、重置密码）。
    - 角色管理：定义系统角色（如超级管理员、运营人员、技术支持等），支持为角色分配特定权限。
    - 菜单管理：动态配置管理后台的菜单结构（层级、排序、显隐控制），并与权限系统联动。
    - 权限分配：实现细粒度的操作权限控制（按钮级权限），确保不同角色的用户仅能操作其职责范围内的功能。

## 4. 开发计划排期（4–6 个月）

> 注：以下为推荐节奏，可根据团队规模和资源情况微调；核心原则是**先打通 Web 用户端主链路，再扩展管理端和小程序**。

### 4.1 阶段划分概览

- **阶段 A（第 1–2 个月）：打底与首个闭环**
  - 完成后端基础服务与 Dify 云服务接入。
  - 完成 Web 用户端的账号 + 项目/文档基础能力。
  - 打通“论文润色助手”完整闭环（文本输入 → 调用 Dify → 结果写回文档）。

- **阶段 B（第 3–4 个月）：三智能体齐备 + 管理端上线内测**
  - 在 Web 端补齐临床论著助手（精简版）与医学翻译助手功能流。
  - 在 Web 端接入会员订阅基础流程：展示订阅状态、支持选择基础套餐并发起订阅/续费（通过微信扫码支付完成），结果写入统一会员服务。
  - 上线 Web 管理端的基础监控、Dify 应用映射与智能体/模型配置、订阅/订单概览以及第三方服务、微信管理与支付管理功能。
  - 启动小规模种子用户内测，收集日志与反馈。

- **阶段 C（第 5–6 个月）：小程序精简版 + 性能与稳定性优化**
  - 上线小程序用户端（润色 + 翻译精简版），联调 AI 网关/Dify。
  - 在各端强化监控、安全、性能与异常恢复。
  - 修复内测问题，准备 MVP 对外发布。

### 4.2 详细排期

#### 阶段 A（第 1–2 个月）：基础能力 + 润色闭环

- **后端 & AI 网关**：
  - 搭建用户服务、项目/文档服务基础接口。
  - 集成 Dify 云服务：配置润色应用，完成统一调用封装（含错误处理与日志记录）。
- **Web 用户端**：
  - 完成登录/注册页面与基础布局。
  - **完成项目列表、项目详情、文档上传与预览**：
    - 实现 Word 文档在线渲染与交互式编辑功能。
    - 支持保留格式（字体、段落、样式、图片、表格）的在线查看与编辑。
  - **实现"论文润色助手"对话界面与流式输出**：
    - 实现 AI 生成内容的流式展示（逐字渲染）。
    - 实现将润色结果实时流式写回 Word 文档的能力，用户可边生成边查看文档更新。

#### 阶段 B（第 3–4 个月）：功能拓展 + 管理端

- **Web 用户端**：
  - **完成"临床论著助手（精简版）"表单页和结果写回流程**：
    - 实现 IMRAD 结构生成 + 引言/讨论初稿的流式输出。
    - 支持将生成内容实时流式写入 Word 文档。
  - **完成"医学翻译助手"短文本翻译与页面展示**：
    - 实现翻译结果的流式输出展示。
  - 对智能体工作区的交互体验进行一轮打磨（加载状态、错误提示、新手引导等）。
- **Web 管理端**：
  - 实现用户/项目/调用次数等基础统计页。
  - **实现系统权限管理体系**：完成用户管理、角色管理、菜单管理及细粒度的权限分配功能。
